# E9-Bridge CLI 작업 인계

## 현재 상태

- 기존 웹은 React/Vite와 Express로 구성된다. Google·카카오 로그인 구현이 있다.
- 웹 데모의 `/nearby`는 안산 예시 데이터에서 식료품·통신·의료를 검색한다. GPS 거리 및 반경, 지역 직접 선택, 위치 실패 안내, 네이버 지도 링크가 연결되어 있다. 실제 업체 추천과 전화 확인은 운영 데이터가 필요하다.
- `/guide`는 귀국과 장기 정착 항목을 기기에 저장하며 기존 정산 화면, 지역 지원 안내와 공식 출처로 연결한다.
- `npm run build`, `npm run check:lang -w frontend`, Edge 모바일 뷰포트에서 위치 허용·거부, 지역·카테고리 선택, 지도 링크, 체크리스트 저장 및 정산 이동을 확인했다.
- Capacitor Android 프로젝트를 생성했고 웹 빌드, Android 동기화, APK 빌드를 통과했다. Android 실기기 검증이 남아 있다.
- 이 폴더는 Git 저장소가 아닌 프로젝트 복사본이다. 기존 파일과 사용자가 작업한 변경 사항을 보존한다.

## 현재 단계 — Android 실기기 확인

- 앱 홈은 근로·체류, 귀국·정착, 내 주변 순서다. 내 주변 상단의 식료품·통신·의료 선택과 의료의 편의점 안전상비의약품 안내를 추가했다.
- Android 로그인과 가입은 기존 배포 서버에 네이티브 HTTPS 요청을 보낸다. Google·카카오는 기존 웹 로그인으로 연결한다. 찜한 장소는 계정별로 해당 기기에 저장하고 마이페이지에서 세 카테고리로 나누어 보여 준다.
- 브라우저에서 네이티브 HTTP 응답을 모의해 로그인, 찜 저장·해제, 새로고침, 계정 분리를 확인했다. Android 기기에서 배포 서버 로그인과 세션 유지 확인이 남아 있다.

- Android 디버그 APK를 빌드하고 APK 서명, 패키지 `com.e9bridge.app`, 위치 권한을 확인했다. 파일은 `frontend/android/app/build/outputs/apk/debug/app-debug.apk`다.
- 브라우저에서 Android 플랫폼을 모의해 앱 탐색, 안산 지역 검색, 지도 링크, 체크리스트 저장, 정산 연결, 뒤로 가기를 확인했다. 웹 탐색과 Google·카카오 버튼도 설정 응답을 모의해 확인했다.
- ADB에서 연결된 기기가 확인되면 앱을 설치해 실제 위치 허용·거부, 외부 지도 열기, 시스템 뒤로 가기와 재실행 시 체크 상태를 확인한다. USB 디버깅 승인과 사용자 실기기가 필요하다.
- JDK 21과 Android SDK는 `%LOCALAPPDATA%\E9Bridge-Android`에 준비했다. 빌드 세션에만 `JAVA_HOME`과 `ANDROID_HOME`을 지정한다.

## 완료 단계 — Android MVP 화면과 이용 흐름

사용자 요청에 따라 설치형 Android MVP를 준비한다. 웹과 공통 React 코드를 활용하고 기존 웹 내비게이션을 보존한다. 운영 지역·장소·지도 공급자·로그인 개편 결정은 보류한다. 안산 시연 데이터를 명확히 표시한다.

1. Android 앱에서 처음 실행하면 근로·체류, 내 주변, 귀국·정착으로 바로 진입할 수 있는 모바일 홈과 공통 탐색을 구현한다. 모바일 환경에서 기존 계정·서버 연결을 전제로 하는 링크를 핵심 MVP 흐름에 노출하지 않는다.
2. 주변 검색, 지역 선택, 지도 열기, 귀국·정착 체크리스트, 기존 기한·정산 안내를 재사용한다. 앱에서 뒤로 가기와 외부 링크가 작동하도록 현재 Capacitor 구현을 확인하고 필요한 최소 변경을 적용한다. 웹 이용 흐름과 URL을 유지한다.
3. 웹 빌드와 Android 동기화를 실행한다. 앱 경로와 기존 웹이 모두 작동하는지 확인한다. 로컬 Android 툴체인 설치와 APK 빌드는 이 세션 밖에서 진행 중이므로 설치·Gradle 실행은 맡지 않는다. 제품 소스 변경 및 검증만 진행하고 정확한 변경 내역과 검증 한계를 보고한다.

## 이전 단계 — Android 데모 빌드 검증

2026년 11월 7일 CLI 실행에서 웹 빌드, 언어 검사, Android 동기화를 다시 통과했다. JDK 21과 Android SDK를 찾지 못했고 Gradle은 Java 확인 단계에서 종료됐다. JDK 21과 Android SDK Platform 36 및 Platform-Tools를 설치하거나 설치 경로를 확인한 뒤 APK 빌드와 실기기 검증을 이어간다.

1. 현재 프로젝트와 이미 설치된 JDK 및 Android SDK 위치를 확인한다. 발견한 설치는 현재 실행에만 환경변수로 연결한다.
2. `npm run build` 후 `frontend`에서 `npx cap sync android`를 실행한다. 필요한 로컬 도구가 있으면 `frontend/android`에서 `.\gradlew.bat assembleDebug`를 실행하고 결과 또는 APK 경로를 보고한다.
3. 도구나 실기기가 없으면 이용 가능한 검증을 완료하고, 빠진 항목과 다음 실행 명령을 최종 답변에 남긴다. 운영 데이터, 로그인 재설계, 네이티브 API 연동, 배포는 다음 단계로 남긴다.

설치가 필요하면 현재 단계는 누락 도구를 식별하고 설치 절차를 보고하는 데서 끝난다. 시스템 설정 변경, 도구 설치, 계정·키 생성, 외부 게시 없이 프로젝트 내에서 작업한다. 현재 단계에 필요한 재현 가능한 프로젝트 수정만 수행한다.

이 단계에서는 CLI 셸 도구로만 검증한다. 셸 도구가 실행되지 않으면 해당 오류를 보고한다.
