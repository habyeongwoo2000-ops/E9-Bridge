# 챗봇 범위 제한 및 근거 기반 응답

## 변경

- 직접 입력한 질문은 서버에서 먼저 범위와 근거를 판별합니다.
- 소규모 서버 KB를 항목 단위로 나누고, 관련 문서 ID 1~4개를 선택한 뒤 선택 문서만 답변 생성에 전달합니다. 별도 벡터 DB는 사용하지 않습니다.
- 범위 밖/조건 부족/근거 부족은 6개 언어 고정 안내로 반환하며 일반 지식 대체 답변을 제거했습니다.
- 문서 ID와 인용 원문이 실제 선택 문서에 존재하는지 서버에서 검사합니다. 출처와 확인일은 서버가 붙입니다.
- 원문 일치 검사는 모든 문장의 사실성을 보장하지 않으므로 `verified: true`로 표시하지 않습니다.
- 직접 입력한 질문의 클라이언트 FAQ 유사도 우회 및 오류 시 키워드 답변을 제거했습니다. 추천 질문 버튼의 정해진 답변은 유지합니다.
- 각 모델 호출은 최대 18초, 요청은 42초 예산으로 제한하며 기존 호출 제한보다 짧은 예산을 지원합니다.
- 서버 응답은 no-store이고, 답변 메모리 캐시 키에 KB 내용 버전이 포함됩니다.

## 배포할 파일

- api/ask.js
- api/_chat-policy.js (신규)
- api/_gemini.js
- assets/app.js

기존 GEMINI_API_KEY 환경변수를 사용합니다. DB 변경/신규 패키지 설치는 없습니다.
정적 파일 캐시 갱신은 별도 담당자와 함께 처리해야 합니다. Python 정적 서버는 API를 실행하지 않으므로 Vercel 미리보기 환경에서 통합 검증해야 합니다.

## 검증

`node --test tests/chat-policy.test.cjs`

이 테스트는 Gemini 응답을 모의한 제어 흐름 테스트입니다. 실제 Gemini의 분류 정확도, 응답 지연, 지원 모델의 구조화 출력 호환성을 검증한 것은 아닙니다.
실제 API로 아래 사례를 별도 평가해야 합니다.

## 한계 및 후속 작업

- 범위 판단과 답변 생성을 모델이 수행하므로 우회/오분류 가능성은 남습니다. 문서 ID와 인용 원문 검증만으로 답변의 의미 전체를 검증하지는 않습니다.
- KB의 법률 내용 및 확인일(CHECKED_ON)은 이번 수정에서 최신성 검토하지 않았습니다.
- 추천 질문 버튼은 기존 브라우저 KB를 사용합니다. 서버 KB와의 자료 통합 및 내용 검토가 후속 작업입니다.
- 자료가 늘면 임베딩/키워드 검색을 추가하고 검토 상태·적용일·출처 URL을 문서 메타데이터로 관리해야 합니다.
- 기존 사용자 화면에 남은 과거 답변은 자동 삭제하지 않습니다. 새 질문부터 적용됩니다.

## 3턴 순서 회귀 테스트 추가 (2026-11-03)

`node --test tests/chat-policy.test.cjs`: 전체 13개 통과 (기존 9개 + 순서/격리 검증 4개).

1. 저녁메뉴 추천 → 정상적인 신청기한 질문 → 동일한 저녁메뉴 추천: 거절/근거답변/다시 거절 경로 확인.
2. 정상 답변의 캐시가 적중한 직후에도 새 메뉴 질문의 범위 판별은 생략되지 않음.
3. 클라이언트가 history/messages/system으로 이전 승인 문구를 보내도 모델의 대화 이력으로 전달되지 않음.
4. 세 번째 질문을 분류기가 잘못 허용했더라도 답변에 유효한 근거 인용이 없으면 응답을 보류함.

현재 API는 매번 현재 질문과 자료만 전달하는 무상태 구조입니다. 화면에 대화가 쌓여도 이전 문답은 모델에 전달되지 않습니다.
모의 테스트는 분류기의 반환값을 지정하므로 실제 모델이 세 번째 질문을 거절할지 검증한 결과는 아닙니다.
또한 유효한 인용문을 붙인 무관한 생성문까지 의미적으로 차단한다고 보장하지 않습니다. 실제 모델 순서 테스트가 별도로 필요합니다.
의도적인 대화 우회는 multi-turn jailbreaking(다중 턴 탈옥)이라고 부를 수 있으나, 단순 반복에서 다른 답이 나온 것만으로 특정 공격 기법이나 대화 이력 오염을 확정할 수는 없습니다.
