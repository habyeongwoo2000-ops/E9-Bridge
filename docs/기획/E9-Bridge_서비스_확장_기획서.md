# E9-Bridge 서비스 확장 기획서

- 작성일 2026년 11월 7일
- 문서 상태 초안
- 대상 기존 웹 서비스와 모바일 앱

## 1. 배경과 목표

E9-Bridge는 고용허가제(E-9) 외국인근로자가 사업장 변경, 퇴사, 기한, 보험금과 정산 절차를 이해하도록 돕는 웹 서비스다. 현재 React/Vite 화면과 Express API를 사용하며 한국어, 영어, 베트남어, 인도네시아어, 크메르어, 네팔어를 제공한다.

11월 3일 멘토링에서는 정보 제공 이후 사용자가 어떤 행동을 할 수 있는지 구체화하자는 의견이 나왔다. 이번 확장은 기존 근로 안내에 두 가지 이용 흐름을 더한다. 평소에는 가까운 곳에서 필요한 생활 서비스를 찾고, 귀국이나 장기 정착을 준비할 때는 자신의 상황에 필요한 절차와 상담 창구를 확인한다. 기존 웹은 링크로 접근하는 접점으로 운영하고, 모바일 앱에서는 같은 기능을 휴대폰에 맞게 제공한다.

### 제품 목표

1. 근로·체류 관련 안내에서 사용자가 기한과 다음 조치를 확인할 수 있다.
2. 생활 정보에서 사용자가 이용할 만한 장소를 찾아 전화하거나 길찾기를 시작할 수 있다.
3. 귀국·장기 정착 안내에서 사용자가 다음 준비 항목과 문의처를 찾을 수 있다.

## 2. 대상 사용자와 검증할 가설

주 대상은 한국에서 근무 중인 E-9 근로자다. 초기 검증 지역과 언어는 인터뷰 참여자를 확보할 수 있는 곳과 실제 장소 데이터 품질을 기준으로 정한다. 베트남어 사용자를 초기 인터뷰 후보에 포함하되, 검증 결과는 해당 지역과 참여자 범위에서 해석한다.

| 가설 | 확인 방법 | 제품 결정 |
|---|---|---|
| 일반 지도에서 장소는 찾을 수 있어도 내 목적에 맞는지 판단하기 어렵다 | 최근 식재료 구매, 선불폰 개통, 병원·약국 방문 경험을 묻고 사용자가 기존 도구로 검색하는 과정을 본다 | 전화, 언어 지원, 상품 취급 등 카드에 우선 표시할 정보 |
| 가까운 순서와 실제 이용 가능 여부를 함께 보면 방문 후보를 쉽게 고를 수 있다 | 같은 과제를 기존 검색 방식과 시제품으로 수행해 결과 선택 이유와 걸린 시간을 비교한다 | 정렬 기준, 확인 정보, 첫 카테고리 |
| 귀국·정착 안내는 항목을 읽는 것보다 순서와 문의처를 함께 볼 때 도움이 된다 | 상황을 제시하고 첫 준비 항목, 준비 시점, 문의할 곳을 찾아보게 한다 | 안내 구조와 우선 공개할 체크리스트 |

## 3. 서비스 구성과 이용 흐름

| 영역 | 진입 상황 | 이용 흐름 |
|---|---|---|
| 근로·체류 | 사업장 변경, 퇴사, 출국 전 정산이 필요하다 | 기존 기한 계산과 절차 화면에서 다음 단계와 관련 기관을 확인한다 |
| 내 주변 | 외국 식재료를 사거나 통신·의료 서비스를 이용하고 싶다 | 카테고리 선택 → 현재 위치 또는 지역 선택 → 장소 목록 → 상세 → 전화·길찾기 |
| 귀국 준비 | 출국 전 처리할 일을 정리하고 싶다 | 출국 준비 체크리스트 → 정산·보험 관련 기존 화면 → 공식 안내와 문의처 |
| 장기 정착 | 앞으로 확인해야 할 체류·생활 정보를 알고 싶다 | 목표 선택 → 준비 항목과 확인할 조건 → 공식 출처와 상담 창구 |

홈에서는 근로·체류, 내 주변, 귀국·정착에 바로 접근할 수 있게 한다. 장소 검색과 안내 열람은 로그인 없이 제공한다. 계정에 정보를 저장하는 기능은 기존 계정 흐름을 활용하고, 체크리스트의 기기 간 동기화는 이용 수요를 확인한 뒤 범위를 결정한다.

## 4. 기능 요구사항

### 4.1 내 주변 생활 정보

- '내 위치 사용'을 선택한 순간에 위치 접근을 요청한다. 권한 거부, 위치 확인 실패, 낮은 정확도에는 시·군·구를 직접 선택할 수 있게 한다.
- GPS 검색은 선택한 범위의 결과를 직선거리 기준으로 표시한다. 지역 검색은 해당 지역 결과로 표시하고, 사용자와의 거리를 알 수 없으면 거리 표기를 생략한다.
- 카드에는 장소명, 유형, 주소, 확인 가능한 전화번호를 표시한다. 한국어 상호와 주소를 함께 제공해 현장 문의나 지도 앱 검색에 쓸 수 있게 한다.
- 연락처가 확인된 경우에 전화 버튼을 제공한다. 길찾기는 목적지를 외부 지도 앱 또는 웹 지도에서 열 수 있게 한다.
- 검색 결과가 없으면 검색 범위 변경이나 인접 지역 선택을 안내한다. 네트워크·공급자 오류는 결과 없음과 구분하고 재시도를 제공한다.

| 카테고리 | 검색 대상 | 확인이 필요한 추가 정보 |
|---|---|---|
| 식료품 | 외국 식료품점, 아시아 식재료 매장 | 국가별 식재료 취급 여부 |
| 통신 | 통신 매장, 선불폰·유심 취급점 | 선불 개통 상담 가능 여부, 방문 전 문의할 내용 |
| 의료 | 병원·의원, 약국 | 진료시간, 통역이나 외국어 응대 여부, 정보 출처 |

장소 기본 정보와 팀이 별도로 확인한 속성을 구분한다. 확인 정보에는 출처와 확인일을 붙인다. 영업·진료시간이나 통역 제공 여부를 확인하기 어려우면 전화 또는 공식 안내를 통해 확인하도록 표시한다.

### 4.2 귀국·장기 정착 콘텐츠

- 귀국 안내는 출국 전 준비, 정산·보험 관련 확인, 문의처로 구성한다. 해당 항목에서 기존 계산과 절차 화면으로 이동할 수 있게 한다.
- 장기 정착 안내는 사용자가 선택한 준비 목표에 따라 확인할 절차, 필요 서류의 공식 안내, 상담 창구를 제시한다. 개인별 체류 자격과 가능 경로는 공식 기관에서 확인하도록 연결한다.
- 콘텐츠는 대상, 적용 조건, 준비 시점, 다음 행동, 공식 출처, 마지막 확인일을 공통 항목으로 관리한다. 번역도 원문 개정과 함께 갱신한다.

## 5. 기술 설계와 운영

- **웹·앱 공통 화면**은 현재 React/Vite 구조와 다국어 체계를 재사용한다. 모바일 패키징은 Capacitor를 우선 후보로 두고, 실기기에서 앱 실행, 뒤로 가기, 외부 지도 열기, 위치 권한을 확인한다. 첫 검증 플랫폼은 참여자가 사용하는 기기와 팀의 빌드 환경을 기준으로 결정한다.
- **API**는 기존 Express에 장소 검색 경로를 추가하는 방향으로 설계한다. 장소 조회와 지도 표시를 분리하고, 화면은 공급자별 응답을 공통 형식으로 받는다. 앱에서는 배포 API 연결과 허용 출처를 별도로 확인한다.
- **장소 데이터**는 장소명, 유형, 좌표, 주소, 연락처, 출처, 확인일을 기본으로 한다. 첫 검증은 한 지역의 소규모 데이터로 진행할 수 있다. 지도·검색 공급자는 반경 검색 지원, 지역별 검색 품질, 표시·저장 조건, 비용을 확인한 뒤 결정한다.
- **계정**은 현재 코드의 Google·카카오 흐름을 기준으로 한다. 앱에서 인증 후 돌아오는 동작과 기존 계정 접근은 실기기에서 확인한다. Zalo 추가와 로그인 방식 개편은 가입 실패 원인이 확인된 후 후속 검토한다.
- **위치정보**는 사용자가 요청한 검색에 사용한다. 정확한 좌표를 계정, 검색 이력, 로그에 보관하지 않는 것을 설계 기준으로 삼고, 외부 검색 사업자에 전달되는 데이터는 공급자 선정 시 확인한다.
- **운영**에서는 장소·콘텐츠별 확인 책임자를 지정한다. 연락처나 운영 정보가 달라진 경우 수정할 수 있게 하고, 확인 기한이 지난 정보에는 재확인 상태를 표시한다.

## 6. 개발 단계와 완료 조건

사용자 검증과 기술 검증을 병행한다. 각 단계는 화면 개수가 아니라 사용자가 끝까지 수행할 수 있는 흐름을 기준으로 종료한다.

| 단계 | 범위 | 완료 조건 |
|---|---|---|
| 1. 발견 및 기술 검증 | 사용자 인터뷰, 후보 지역 장소 데이터 대조, 앱 패키징과 실기기 연결 시험 | 첫 지역과 카테고리 선정 근거가 있고, 앱에서 위치 접근과 API 호출이 재현된다 |
| 2. 생활 정보 MVP | 한 지역·한 카테고리에서 장소 찾기부터 전화·길찾기까지 구현 | 웹과 앱에서 정상 흐름과 권한 거부, 지역 직접 선택, 결과 없음, 네트워크 실패를 확인한다 |
| 3. 첫 공개 범위 확정 | MVP 사용자 테스트, 문제 수정, 기존 기능 회귀 확인 | 사용자가 목표 장소를 찾아 다음 행동을 할 수 있고 기존 기한 계산, 언어 전환, 웹 로그인에 문제가 없다 |
| 4. 카테고리와 콘텐츠 확장 | 검증 결과에 따라 나머지 생활 카테고리 확대, 귀국·정착 체크리스트 공개 | 카테고리별 데이터 확인 기준과 콘텐츠 갱신 책임이 정해지고 사용자가 다음 준비 항목과 문의처를 찾는다 |

## 7. 측정 기준

| 항목 | 측정 방법 |
|---|---|
| 장소 찾기 성공률 | 주어진 상황에서 도움 없이 목적에 맞는 장소를 고른 참여자 비율 |
| 결과 없음 비율 | 검색을 완료했으나 결과가 없었던 요청의 비율. 공급자·네트워크 오류는 별도 집계 |
| 다음 행동 선택률 | 장소 검색 후 전화 또는 길찾기를 선택한 세션의 비율. 실제 문의·방문 성공은 인터뷰에서 확인 |
| 권한 거부 후 이용 가능성 | 위치 접근을 허용하지 않고도 지역을 직접 선택해 과제를 끝낼 수 있는지 확인 |
| 체크리스트 이해도 | 사용자가 첫 준비 항목과 공식 문의처를 정확히 찾는지 확인 |

첫 검증에서 기준값을 수집한 뒤 공개 범위와 목표치를 정한다. 지표 집계는 정확한 위치나 개인 식별 정보 없이 설계한다.

## 8. 후속 결정 사항

- 초기 검증 지역, 첫 카테고리, 실기기 검증 플랫폼을 정한다.
- 네이버 지도와 카카오 로컬 등을 지도 표시와 장소 검색 요구에 따라 각각 비교한다.
- Google·카카오로 가입을 완료하기 어려운 사례와 원인을 확인한 뒤 Zalo 등 추가 공급자 검토 여부를 결정한다.
- 공식 제출 일정은 회의록에 서로 다른 날짜가 기재되어 있으므로 팀의 공식 일정 확인 후 개발 단계에 반영한다.
